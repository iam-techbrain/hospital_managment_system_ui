System Infrastructure & Data Architecture

A comprehensive technical blueprint defining which databases, event brokers, in-memory caches, and storage engines are used, exactly when and where Kafka, Redis, PostgreSQL, and WebSockets execute across each clinical phase.

PostgreSQL (Primary Relational Database)
ACID Compliant Relational Engine

PostgreSQL serves as the primary system of record. Every financial transaction, medical ledger entry, patient demographic, and clinical audit trail requires strict ACID guarantees to prevent data loss or duplicate records.

What PostgreSQL Stores:
  • • Patient Demographics & Identifiers: UHID, ABHA ID, Aadhaar Hash, Phone, Emergency Contacts.
  • • Doctor Clinical Records (EMR): Consultation encounters, ICD-10 diagnoses, medical history.
  • • Consolidated Financial Ledger: Billing line items, insurance claims, receipts, GST tax calculations.
  • • Pharmacy & Inventory Tables: Drug master, batch tracking, unit costs, vendor invoices.
Isolation Level: Read Committed / Serializable PostgreSQL 16 Enterprise
Redis (In-Memory Data Store & Cache)
Sub-Millisecond Cache & Locks

Redis handles high-frequency volatile states that change multiple times per second, ensuring zero latency on front desk queues and ward occupancy displays without hitting the disk database.

Where Redis is Used:
  • • Live OPD Token Queue: Redis sorted sets (ZADD / ZPOPMIN) for ordering patient queue tokens.
  • • Distributed Concurrency Locks (Redlock): Prevents simultaneous double-booking of the same ICU bed or OT room.
  • • Session Storage: User authentication sessions, doctor active consultation states.
  • • API Rate Limiting: Protects authentication endpoints and OTP generation against abuse.
Latency Target: < 2 milliseconds Redis Cluster 7.x
Apache Kafka (Event Streaming & Message Broker)
Decoupled Asynchronous Event Bus

Kafka enables event-driven architecture across decoupled hospital microservices. When a doctor writes a prescription or a patient arrives, downstream departments react in real time without blocking the primary user interface.

When Apache Kafka is Used:
  • • Prescription Finalized: Topic prescription.finalized notifies Pharmacy (dispensing queue), Lab (sample collection), and Billing (charge accumulator) simultaneously.
  • • Emergency Triage Alerts: Topic triage.code-red triggers instant alarms across resuscitation bays and pager alerts to on-duty specialists.
  • • Notification Pipeline: Decoupled workers consume events to dispatch SMS, WhatsApp confirmation links, and email invoices.
  • • Immutable Audit Log: Logs every clinical modification for legal and regulatory compliance.
Partitioning Key: patient_uhid Kafka 3.7 / Strimzi
AWS S3 / MinIO (Object Storage)
High-Durability Medical Storage

Relational databases degrade if gigabytes of binary scan files are stored in tables. High-resolution DICOM radiology scans, laboratory reports, and digital bills are stored in scalable, encrypted object storage buckets.

What Object Storage Holds:
  • • Radiology Imaging (PACS / DICOM): High-resolution Chest X-Rays, 128-slice CT scans, and MRI scans.
  • • Signed Laboratory PDF Reports: NABL accredited laboratory test result certificates.
  • • Official Discharge Papers & Tax Invoices: Signed PDF discharge summaries and gate passes.
  • • ABHA Digital QR Cards: Cached digital identification cards for offline patient access.
Encryption: Server-Side AES-256 S3 Standard / MinIO Cluster

Microservices Architecture
  • 1. Patient & Identity Service: Handles UHID generation, ABHA M1 registration, and demographic data. Backed by PostgreSQL.
  • 2. Clinical EMR & Consultation Service: Manages doctor encounter notes, ICD-10 searches, and E-Prescription signing. Emits Kafka events on finalize.
  • 3. Bed & OT Resource Service: Maintains live bed state and OT availability. Employs Redis Redlock and WebSockets.
  • 4. Laboratory (LIS) & Diagnostics Service: Manages test queues, machine analyzer inputs via HL7/FHIR, and stores PDF reports in S3/MinIO.
  • 5. Central Invoicing & Ledger Engine: Consolidates departmental charges asynchronously via Kafka consumers into an ACID billing ledger.
Kafka Topics & Event Contracts
  • appointment.booked

    Fired when a patient schedules a visit. Consumed by SMS worker and OPD queue pre-loader.

  • prescription.finalized

    Fired when the doctor signs an E-Rx. Consumed concurrently by Pharmacy, Lab, and Billing.

  • triage.code-red

    High-priority emergency event. Triggers instant pager alerts to resuscitation teams.

  • lab.report-verified

    Fired when pathologist signs a test. Pushes PDF link to patient portal and doctor EMR.

  • patient.discharged

    Fired on cashier no-dues clearance. Releases IPD bed status back to cleaning mode.
